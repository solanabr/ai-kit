# Changelog

All notable changes to solana-ai-kit.

## [Unreleased]

### Added
- **The decision record, the hooks that hand it to every agent, and a guard that keeps it the main session's** (`HOOK_SET_VERSION` 4; `/update`'s hook migration registers all four on existing installs, so this is not fresh-install-only). A decision reached an agent only if someone copied it into the agent's brief, and a brief is frozen when written, so agents re-asked or overrode what the user had settled. The record keeps the user's decisions, principles and standing orders under the clone's git directory, and the hooks push the ones in force into the session and every subagent. The full write-up is `docs/decisions.md`.
  - **`.claude/bin/decisions.sh`** writes it: `add`, `supersede`, `in-force`, `hash`, `export [--handoff]` and `path`. One file per entry under `$(git rev-parse --git-common-dir)/decisions/`, so every worktree of a clone shares one live record and nothing is committed or pushed; `in-force.md` holds a line per entry in force, kept near 1.5K tokens. Only the user's own call supersedes one of their decisions, a standing order must name what it covers and when it expires, and a credential-shaped field is refused without being echoed. `--stdin` takes the fields through a quoted heredoc, for words spanning lines and for text naming a credential path, which a guard can read on the command line as a file the call opens. It runs without a prompt at Off, Relaxed and Medium under rule set 10's `Bash(bash .claude/bin/decisions.sh *)`, and under an earlier rule set it may prompt at those tiers; inside High's read fence it is not supported yet.
  - **`decisions-inject.sh`** (SessionStart, SubagentStart) hands the session and every subagent the list, Explore and Plan included. **`decisions-push.sh`** (PreToolUse, every tool) hands an agent the list again, once, when it changed since that agent last saw it, keyed on `agent_id`, so a decision made mid-task reaches a running subagent at its next tool call. **`decisions-report-check.sh`** (SubagentStop) sends one of the kit's agents back once when its report leaves out Verified, Decisions made, Decisions needed, Assumptions or Next owner.
  - **None of those three can block a tool call:** each is registered behind a wrapper that exits 0, and none makes a model call. The two record hooks print nothing in a repository without a record, ignore a symlinked one, and cut the list under Claude Code's 10,000-character context cap. This supersedes 2.2.0's two-event hook set; still nothing formats files, runs builds or echoes after a tool call or a turn.
  - **`decisions-guard.sh`** (PreToolUse: Bash, `Write`, `Edit`, `MultiEdit`, `NotebookEdit` and context-mode's tools) refuses a subagent's writes to the record through the helper's write verbs and the file tools, at every tier; other write routes are a documented limit. Whatever the record holds reaches every agent as the user's decision, and an agent testing the helper by hand once wrote entries into a real record. The guard refuses a subagent, which Claude Code marks with an `agent_id` in the hook payload, when it runs `decisions.sh add` or `supersede` or aims a file tool inside the record directory; the main session passes before anything is parsed. Every agent can still read the record and run the helper's readers, a command that only names the helper is not a call, and the refusal tells the agent to report the decision under Decisions made or Decisions needed instead.
  - **`CLAUDE-solana.md`:** ask before acting when the answer is the user's to give (product intent, a material change to scope or architecture, contradicting their decision, an operational approval), as a brief with a recommendation and the case against; never re-confirm an instruction or a decision in force; an Open item carries a recommendation rather than a pointer; and a subagent ends its report with the five labelled lines the check reads.
  - **`/doctor`** gains check 12, the hooks' wiring (live, predating, a script or a file the write guard reads missing, removed on purpose or partly hand-edited), and check 13, the record (absent, linked, stale after a hand edit or deletion, or past the cap).
  - **Plugin installs** get the hooks and no helper, having no `bin/`; **`--agents` installs** get the helper, and the hook scripts unregistered, having no settings file.
  - **Tests:** `tests/test_decisions.sh`, `tests/test_decision_hooks.sh` and `tests/test_decisions_guard.sh`, the first and last of which `tests/run_all.sh` now requires; `test_settings_deep.sh` and `test_hooks.sh` expect the four events and hold the wiring, and `test_update_settings_migration.sh` compares each script's registrations with what the kit ships, since one script now runs on two events.

- **`git --config-env` and `git reflog delete`/`drop` are denied at every tier, and High fences a repository's `.git/config` and `.git/hooks/` from the file tools** (`RULE_SET_VERSION` 7). Additive, and `/update`'s rule-set catch-up re-applies the declared tier, so existing installs receive all of it.
  - **`Bash(git --config-env*)`**, beside `Bash(git -c *)`. `--config-env` is `-c` reading its value from an environment variable, so `X=/tmp/x.sh git --config-env=core.fsmonitor=X status` runs `/tmp/x.sh` — and a harmless probe of the `=` spelling got past the permission layer on rule set 6. One rule covers both spellings because its `*` touches the option name: a `*` touching a non-space may be empty and matches `=` as readily as a space, where the ` *` the `-c` rule has would have required the space. `tests/test_firewall.sh` pins both facts with the ported matcher, the planted spaced shape included. A leading `VAR=value` is no way round it: a deny rule matches past any leading assignment.
  - **`Bash(git reflog delete *)` and `Bash(git reflog drop *)`**, beside `reflog expire`: they take away the same record a dropped commit is recovered from. One trailing wildcard each, so the bare subcommand needs no twin. `reflog show`, `list`, `exists` and a bare `git reflog` stay open, asserted against the whole generated deny set at every tier.
  - **High denies `Edit(**/.git/config)`, `Edit(**/.git/hooks)` and `Edit(**/.git/hooks/**)`**, and in a linked worktree whose common git directory sits outside the project the same three for that directory by absolute path, emitted under the condition `git_common_write()` already emits it into `allowWrite` — so no machine path reaches the kit's committed `settings.json`. Measured first: Claude Code's own sandbox already refuses shell writes to the project's `.git/config` and `.git/hooks/` at every tier that runs it (with `.git` in the kit's `allowWrite`), while the file tools treat those as protected paths that prompt, go to auto mode's classifier and are written unasked under `bypassPermissions`. Only a deny holds in every mode, so the rule set adds nothing to the sandbox side. Not filesystem-wide: an `Edit` deny also reaches the sandbox as a write deny (measured), and `//**/.git/config` would refuse every `git clone` and `git init` at High. Relaxed and Medium are byte-identical to rule set 6 for this group.
- **`egress-guard.awk`'s `GITCFG` pass: `-c` and `--config-env` behind another git-level option**, denied at every tier. Both rules are anchored on the first token after `git`, so `git --no-pager -c core.fsmonitor=/tmp/x.sh status` reached neither a rule nor a hook on rule set 6. The pass mirrors the rules the way `GITDESTRUCT` mirrors the subcommand ones: it fires only when the option follows another one, leaves the first-position spelling to the rules, and treats a commit message, a `--grep` pattern or an `echo` naming either option as data.

- **The half of 2.4.0's `git config` deny that a permission glob cannot express, as a hook** (`HOOK_SET_VERSION` 2; the guard reaches existing installs through `/update`'s `hooks/` copy, so this is not fresh-install-only). 2.4.0 denied `Bash(git config *alias.*)` and its zero-gap twin and said in its own entry what it left open. Both gaps are now closed in `egress-guard.awk`'s new `GITEXEC` pass, **denied at every tier**:
  - **Case.** Git's section and variable names are case-insensitive and a permission glob is not, so `git config Alias.z '!git clean -fdx'` walked straight past both rules — confirmed upstream by writing `Alias.Y` and reading it back with `--get alias.y`. No glob set can fix this: `alias` alone has 32 case spellings, and that is one key of seven. The guard normalises the key's two ends to lowercase before comparing, leaving the middle subsection case-sensitive the way git does, so `Credential.https://GitHub.com.HELPER` resolves like `credential.helper`.
  - **The other code-executing keys** — `core.pager`, `core.editor`, `core.hooksPath`, `sequence.editor`, `credential.helper`, `diff.external` — each name a program git runs later and were covered only in the one-shot `git -c key=value` form, via the blanket `Bash(git -c *)` deny. Now covered as writes in every spelling: bare, `--global`, `--local`, `--system`, `--worktree`, `--file <f>`/`--file=<f>`/`-f <f>` (whose operand is consumed, so the key cannot hide behind it), `--add`, `--replace-all`, the newer `git config set`, and `--rename-section` onto a section whose variables would become executing keys.
  - **`git config --edit`**, `-e` and the `edit` subcommand, which open an editor on the config and name no key at all.
  - **Reads are deliberately NOT gated**, which narrows the shipped behaviour: the globs caught `git config --get alias.z` as collateral nobody minded, and a hook can be precise, so `--get`, `--get-all`, `--get-regexp`, `--get-urlmatch`, `--list` and `-l` stay silent, as do the removers (`--unset`, `--unset-all`, `--remove-section`) and the bare key-with-no-value form, which is a read.
  - **No tier ladder**, unlike the force-push and history-rewrite gates in the same guard: what is stopped is not a destructive act whose blast radius a tier could scale, it is a key that makes git execute an attacker-chosen command at some later, unrelated moment, possibly in a different session, and no agent workflow needs `core.hooksPath` or an alias set on the user's behalf. Off still disables the hook, like every other gate.
  - **2.4.0's two glob rules stay.** They decide at the permission layer, before the hook runs, and a hook miss is a silent open door where a glob is a loud closed one.
  - **Still open, and not claimed otherwise:** a shell redirect into `.git/config` is not a `git config` command, so neither a subcommand glob nor a subcommand-parsing hook has anything to anchor on, and `.git` is in `sandbox.allowWrite` with no `Edit` deny over it. `GIT_CONFIG_GLOBAL` in the environment points git at another config file and stays open, since agents use it to keep the user's config out. The `GIT_CONFIG_COUNT` family, `git -c` by another name, is closed by the entry on #260's review findings below.
- **The destructive git subcommands, when reached behind a git-level option** (`egress-guard.awk`'s new `GITDESTRUCT` pass). Every destructive-git deny is a glob anchored on the literal subcommand, so a git-level option sits where the glob expects `git` and none of them match. `Bash(git -C *)` is one of the many option forms `git --help` lists before `<command>`, and with `git -c` one of only two shut — measured against the live `Bash(git clean *)`, `git --no-pager clean --dry-run`, `git --git-dir=.git clean --dry-run`, `git -P clean --dry-run` and `git --literal-pathspecs clean --dry-run` all ran, while `git -C . clean --dry-run` was denied. Each form takes both `--opt=v` and `--opt v` and repeats and combines freely, so no glob set enumerates them; one option walk does, and `git config`'s walker already had to do it.
  - **It mirrors the deny rules and changes no tier's policy.** It fires only when a git-level option precedes the subcommand, because the unprefixed spelling is already decided at the permission layer by a rule that applies at every tier, and re-deciding it here would put a hook predicate in front of commands a glob handles correctly today. Each predicate is the rule it mirrors or narrower: `--ha` and `--mirror` are matched as token prefixes where the glob matches the substring anywhere. `git clean --dry-run` is denied because `Bash(git clean *)` denies it; the hook does not loosen that, and `git restore --staged <path>` is denied for the same reason even though `--staged` alone only unstages.
  - **Mirroring includes the bare form.** A trailing ` *` that is a rule's only wildcard is optional in Claude Code's matcher — documented, and verified live: bare `chown` is refused by `Bash(chown *)` with no twin beside it — so `Bash(git clean *)` denies a bare `git clean`, and `git --no-pager clean` is denied to match. As first merged, the pass required an argument after `clean`, `restore`, `checkout --` and `reflog expire`, on the belief that the glob needed one too, which left the prefixed bare form open in both layers. For `clean` that was live: with `clean.requireForce` false a bare `git clean` deletes untracked files, and `git --config-env=clean.requireForce=V clean` sets it inside the same command line, behind an option no glob sees past.
  - **In:** `clean`, `restore`, `checkout -- <path>` and `reset --hard` (destroying uncommitted work, which is in no reflog); `reflog expire`, which `FIREWALL-SPEC.md` §3.4 singles out as what makes history unrecoverable; `prune`, which with no `--expire` deletes every unreachable loose object whatever its age — what `git fsck` recovers a dropped stash from, or a deleted branch no reflog still reaches — and which `Bash(git prune *)` already denied at every tier, so an open prefixed spelling made that rule decorative (the subcommand only: `worktree prune`, `remote prune`, `prune-packed` and `fetch --prune` stay silent, each asserted); `push --mirror`, which overwrites every ref on the remote for everyone; and the `--upload-pack`/`--receive-pack`/`--exec` transport overrides, which name a *program* for git to run while `git push/pull/fetch` are three of the eight sandbox `excludedCommands`, so that program runs with the sandbox lifted.
  - **Out:** `git branch -D`/`--delete`/`-f`, on purpose — reflog-recoverable, and the worst parsing surface in the set (`-D` against a safe `-d`, `-f` clustered inside `-Df`, and `--sort=-date`, which already tripped a `-d` matcher in this same guard once). `git gc --prune`, as a recorded gap rather than a verdict that it is safe: it deletes the same unreachable set `prune` does. For both the glob rules remain the only layer and the prefixed form stays open.
  - **Known misses, stated rather than papered over:** a variable-indirected command (`G=git; $G clean -fd`) and git inside a script the agent wrote are invisible to any hook — only the OS sandbox is left there, and `.git` is in its `allowWrite`. `git checkout <tree-ish> -- <path>` and `git checkout --force -- .` are open in both layers, because the glob is `git checkout -- *` and this pass mirrors it rather than widening it. A mis-modelled global option costs a miss, never a false positive: the walk lands on the wrong token, finds no subcommand it knows, and stays silent.
  - **`Bash(git -C *)` and `Bash(git -c *)` are not lifted.** They decide at the permission layer, ahead of the hook, and the hook covers a narrower subcommand set than the rules do — `branch -D` and `gc --prune` behind `-C` are still the rules' job alone.
- **`tests/test_git_guard.sh`** — 201 checks, and in `run_all.sh`'s `required` list because this gate's whole value is in what it does *not* fire on. Two thirds of it is the false-positive corpus: every read form, every remover, `user.email`, `user.name`, `core.autocrlf`, `remote.origin.url`, `push.default`, `init.defaultBranch`, the key named in a commit message, an `echo`, a `--grep` pattern, a `git grep` argument and a heredoc body. Each expectation is paired with a **mutation control** that replays it against a deliberately broken copy of the guard and fails unless the verdict flips — the case fold removed, each of the seven keys dropped from the table one at a time (the list read out of the guard, so a key added later gets a control for free), `--get` moved out of the read set, `user.email` added to the table, and the subcommand anchor removed. For the destructive pass: the prefixed-only scope removed (so the hook starts deciding what the globs own), each included subcommand switched off one at a time, `branch` *added* to the set — because "`git --no-pager branch -D x` stays silent" is only worth something if the suite would notice it being gated — `prune` matched as a substring, which must gate `prune-packed`, an argument required after `clean` again, which must reopen the bare `git --no-pager clean` and nothing else, and an operand-taking global option dropped from the walk, which must cost a miss on the `--git-dir .git` spelling while the `--git-dir=.git` spelling still fires.
- **A varlock `.env.schema` ships next to `.env.example`, and varlock is now the recommended way to manage keys.** [varlock](https://varlock.dev) validates `.env` against a committed schema and can resolve values from a secret manager. `.env.schema` declares `.env.example`'s ten keys in the same order with empty values, each with its description, `@sensitive` (`@sensitive=false` for `THEGRID_GRAPHQL_ENDPOINT`), `@optional` and, on the three endpoint keys, a `url` type, so it is safe to commit and for an agent to read. Validated with varlock 1.23.0: `varlock load` passes with no `.env` and with a sample one, and rejects a `QUICKNODE_WSS_URL` that is not `wss://`. `install.sh` copies it in both modes and `/update` adds it when missing; neither overwrites an existing one, and both append the kit's keys it lacks, each block carrying its own `@sensitive` and `@optional`: `.env` receives every kit key, and varlock treats a key its schema does not declare as required. A key the project declares in any spelling varlock accepts counts as declared, a symlinked schema is never written through, and one that is not writable is left alone with its missing keys named. It is not gitignored. Nothing else changes: `.env.example`, `.env` and `/setup-mcp`'s flow stay as they were, no read rule is added, and `/setup-mcp` only closes with a one-line recommendation. `docs/configuration.md` gains "Secrets with varlock": `varlock load`, `varlock run --inject vars -- claude`, handing a key to one stdio MCP server instead, the preview `varlock proxy run`, and what none of it hides from the agent — `varlock printenv` prints raw values to whoever runs it. `tests/test_env_keys.sh` holds the schema to `.env.example`'s keys in order, with empty values and explicit decorators; `tests/test_env_schema.sh` covers install, update and `git check-ignore` in both modes.

- **`gh api` can no longer write a repository secret or variable at Relaxed, and a workflow dispatch, deployment or environment change through it asks first** (#159). `Bash(gh secret set *)` and `Bash(gh variable set *)` deny at every tier, but `gh api --method PUT repos/O/R/actions/secrets/NAME` reaches the same endpoint, and `Bash(gh *)` in the allow list ran it with no prompt below Medium. A glob cannot tell that PUT from the POST that adds a comment, so `egress-guard.sh` now reads the method and the path together.
  - **What fires:** PUT, POST or PATCH — from `-X`/`--method`, or implied by `-f`/`-F`/`--raw-field`/`--field`/`--input` as gh itself implies it — against a `secrets` or `variables` endpoint (repository, organization, environment, Dependabot, Codespaces), or against workflow `dispatches`, `repos/O/R/dispatches`, `deployments` (Pages included) or `environments`. With or without a leading slash, as a full or GHES URL, with gh's `{owner}`/`{repo}` placeholders quoted or not, and with the owner/repo held in one expansion (`repos/$GITHUB_REPOSITORY/…`). A method the hook cannot read (`-X "$M"`) counts as a write. The wrappers the other passes look past — env assignments, `command`, `timeout`, `sh -c`, subshells, command substitution — are looked past here too, and the pass runs ahead of the egress ladder so an earlier ASK cannot shadow it.
  - **Per tier:** secrets and variables are denied at Relaxed, Medium and High, headless included — the same write the two `gh` denies exist for, so a ladder would make Relaxed's copy of them decorative. Dispatches, deployments and environments ask at Relaxed (silent headless, so the kit's own Action is unaffected) and deny at Medium and High, which is what `Bash(gh api *)` already gives the bare command there — so a wrapped form now gets the same answer. - **`skills.sh` no longer reads a long list as missing a line it holds.** `has_line` was `printf … | grep -qxF` under `pipefail`, so whenever `grep` stopped at its first match before `printf` had written the rest, the pipeline failed and the line read as absent; on Linux, with a list past the pipe buffer, that was every time, and it surfaced in CI as `printf: write error: Broken pipe` in `test_anthropic_skills`. - **`test_validate` says why `validate.sh` failed** when a run that should pass does not, printing the lines it failed on, so an intermittent failure in CI shows its cause.
- **Every word of a command is read as bash reads it (#297).** #294 unquoted only the command word, so on main a quoted subcommand or flag still hid the command from the anchored patterns. `npm "publish"` and `npm 'publish'` passed the publish gate at every tier. `git "push" --force`, `git push '--force'` and `git push origin '+main'` passed High's force-push deny, and `anchor "deploy" … mainnet` and `solana program "deploy" … mainnet-beta` passed at High. `kit_unq` now reads every word of the text those patterns read, under the same rule as before: the quotes must close inside the word and the result must be plain, with `=` and `,` allowed after the command word. A quoted run that spans words, such as a commit message, stays as written.
  - **A quote inside a word** (`a"n"chor deploy …`, `npm pub"l"ish`, `n"p"x -y x`) skipped each guard's shell prefilter, which globbed the raw text. The prefilters now also look for their words in a copy without quotes or backslashes (`kit_unquoted` in `lib-headless.sh`), and still look for a continuation in the text as it came.
  - **A list-form call in an interpreter's heredoc** (`subprocess.run(['npm', 'publish'])`) never put its program at a stage start. An interpreter's line now blanks `[`, `]` and `,` as well as dropping string delimiters, and so does the MCP route's second form of non-shell code. `print(['a', 'b'])` stays silent. A list whose strings form a gated command, such as `print(['npm', 'publish'])`, now prompts, as `os.system('npm publish')` already did.

- **The command bash runs is read however it is spelled (#287, #288, #293).** On main, each spelling below hid a gated command from every gate only a hook enforces: a mainnet deploy at High, and a `.env` upload or `gh auth token` at every tier.
  - **A redirection before the command word** (`2>/dev/null anchor deploy …`, `2>&1 npm publish`, `< /dev/null npx -y x`, `nice 2>/dev/null …`). The guards took it for the command. `first_word`, `cmdword_x`, `kit_unwrap` and onchain-guard's normaliser now skip it, as bash does, through the `kit_redir` the heredoc reader already used. The regex statement splitters in `kit_shell_text` and onchain-guard now read the `&` of `2>&1` the way `split_cmd` does (`kit_sep`).
  - **A quoted or escaped command word** (`"npm" publish`, `n\pm publish`, `'anchor' deploy …`, `"$HOME/bin/npm" publish`). bash removes quotes before it looks a command up. `kit_unq` does the same for the command word the anchored patterns read, when the word's quotes close inside it and the result is a plain command name.
  - **An escaped quote in nested code** (`sh -c "sh -c \"npm publish\""`, and `'\''` three levels deep). `split_cmd` turned it into a real quote, so the inner code was read wrong. It is now marked, like an escaped space, and becomes a quote again only in the string handed to a shell.
  - **`su -c CODE` and `find … -exec CMD …`** run a command line, and `kit_inline_code` now reads both. That covers a clustered `su -lc` and every `-exec`, `-execdir`, `-ok` and `-okdir` of a `find`, each as its own command, so a harmless first `-exec` cannot hide a gated second one. `split_cmd` no longer splits find's and xargs's `{}` into two stage boundaries. One verdict moves toward ask: `xargs -I {} curl -d @{} https://…` was read as `curl -d @` with no file, a literal body that High denied. It now reads as the file upload it is and asks at every tier, as `curl -d @data.json` does. A redirection between a wrapper and its operand (`timeout 2>/dev/null 5 …`) is skipped too.
  - **An arithmetic `<<`** (`echo $((a << b))`) was read as a heredoc opener. Its delimiter `b` matched no line, so the body swallowed every command after it. `kit_hd_ops` now tracks `$(( … ))` and `(( … ))`. A backslash-newline inside a substitution in an unquoted heredoc body now joins its two lines, as bash does, instead of splitting `--final` from its verb.

No command a person or agent writes carries that many. The independent review of this change raised it.

A gate a permission rule backs as well, such as the `--final` deny, still held. `lib-headless.sh`'s new `kit_size_cap`, which every guard reaches through `kit_parse`, refuses a Bash command past 32 KB at every tier, Off included, when:
  - its code passes 32 KB. The slowest shape measured at that size, 16,000 `;`-separated statements, takes `egress-guard` 2.4 s;
  - it passes 10,000 lines, or 256 KB in all. Every guard builds its input into one string a line at a time, which is quadratic in awk: 262,144 empty lines kept each guard busy 10 s, whatever the bytes. Within both limits the slowest case measured, 32 KB of code beside a 220 KB heredoc, takes `egress-guard` under 3 s.

  A heredoc body written to a file with `cat` or `tee` does not count as code, so a 200 KB file written that way passes in under half a second. `kit-code-size.awk` leaves a body out only when all of these hold, and counts it otherwise:
  - the shell reads the `<<` as an operator, outside every quote and substitution (`cat '<<EOF'` is a quoted string, and `bash -c "$(cat <<'EOF' …)"` runs the body);
  - the command it feeds is `cat` or `tee` as the command word itself, not behind a wrapper or a shell: the guards disagree on which words to look past, and `egress-guard` reads `bash cat <<EOF` as a body fed to bash;
  - nothing on the line hands the body on (`cat <<'EOF' | bash`), and the line neither continues onto the next nor is continued from the last;
  - the delimiter is quoted or the body runs no `$( … )`, and the delimiter line arrives.

  MCP payloads keep their own 32 KB cap. `FIREWALL-SPEC.md` had called Bash exempt because the sandbox backs a pattern miss, but the sandbox does not back the gates only a hook enforces, and Off has no sandbox at all.

The pre-firewall `ask` rules had been retired so Relaxed could stay CI-safe, and the replacement hooks only ever covered mainnet, publish, irreversible on-chain, secrets and egress. Now reimplemented, each by the mechanism that can actually express it:
  - **`solana-keygen new`/`recover --force` with no `-o`** is denied at every tier by `secrets-guard.sh`. It destroys `~/.config/solana/id.json`, which never appears in the command text, so the guard's argument scan could not see it — the target is implied by the *absence* of `-o`. A hook rather than a rule because no glob can express "and no `-o`": a deny on `solana-keygen new *--force*` would also stop `--force -o target/deploy/x-keypair.json`, which is how a program keypair is regenerated. A deny rather than a prompt because without the flag `solana-keygen` already refuses to overwrite, so dropping it runs the identical command wherever no wallet exists.
  - **Force push and `gh pr merge`** are gated by `egress-guard.sh`: allowed at Relaxed, ask at Medium, denied at High. This covers `--force`, `--force-with-lease`, `--force-if-includes`, `-f` and the `+refspec` form (`git push origin +main`) that a glob cannot express at all; `--dry-run`/`-n` is exempt.
  - **`npm`/`cargo publish` now asks at Relaxed** instead of being allowed, which is what README and the spec always claimed. Safe at the CI tier because `kit_ask` goes silent with no interactive user; Medium and High still deny, headless included.
  - **Recoverable history rewrites ask at High** — `git rebase`, `git commit --amend`, `git stash drop`/`clear`, `git branch -d`, `git tag -d`/`--delete`, `git filter-branch`/`filter-repo`, with `git rebase --continue`/`--abort`/`--skip` exempt so a conflict resolution is never interrupted. Named one by one so the claim is checkable.
  - **The `--receive-pack`/`--upload-pack`/`--exec` transport overrides** are denied at every tier, on `push`, `pull`, `fetch`, `clone` and `ls-remote`, each with its zero-gap twin. These name a *program* for git to run, and `git push/pull/fetch` are three of the eight `excludedCommands`, so the program would have run with the OS sandbox lifted. **`gh issue delete`** joins them: GitHub cannot undo it.
  - **`gh api` is denied at Medium and High**, closing the `gh api -X DELETE /repos/O/R` route around `gh repo delete` and the `gh api --method PUT …/secrets/NAME` route around `gh secret set`. The whole subcommand rather than the mutating methods: a glob carries no argument form, and a hook classifying the method would be one missed spelling away from a silent hole. `FIREWALL-SPEC.md` §7 item 2 recorded this as an open call; it is now narrowed at the two tiers that promise it and accepted at the two that do not. ## [2.2.0] - 2026-10-02

### Added
- **Agentic firewall with four tiers** — `Off / Relaxed / Medium / High`, default **Relaxed**, gating file access, destructive commands and egress. The tier is recorded in `.claude/security.json` together with the exact rule strings written (`enforced.ruleIds`) and a hash; `.claude/bin/firewall.sh` regenerates the `permissions` + `sandbox` block in `.claude/settings.json` **wholesale** on every switch. Lists merge and never override across settings sources (effective policy is `deny = ∪denies`, `ask = ∪asks − deny`, `allow = ∪allows − deny − ask`), so a layered tier system would collapse to the strictest tier any layer ever wrote; whole-block regeneration is the only way a tier can be *lowered*. Tier-varying path decisions live in `sandbox.filesystem.denyRead`/`allowRead`, the one layer in Claude Code with a genuine carve-out (narrowness decides, not source order, so it survives merging).
- **`/firewall` command** — show the current tier and switch between them.
- **Egress guard hook** — a position-anchored PreToolUse gate for data-carrying `curl`/`wget`. It reads argument *positions*, not command prose, so `--upload-file`/`@file` bodies and reader→network-sink pipelines are caught while documentation, commit messages and issue bodies that merely *name* a credential path are not.
- **`permissions.deny` is identical at every tier** — the never-allowed set: credential stores and vaults, code-execution-on-next-build files (`~/.cargo/config.toml`, `~/.zshenv`, `~/.gitconfig`, in-project `**/.cargo/config.toml`), login-shell and autostart persistence, shell/REPL history, the kit's own settings and hooks (as `Edit(...)`, not `Read(...)`, so the kit can still read its own config), `Bash(claude *)` policy re-roll, and matcher-evading wrappers (`env`, `sh -c`, `git -c`, `git -C`, `flock`, `docker exec`, …). Deny is the one axis where merge-monotonicity is harmless, because every tier agrees.

### Fixed
- **Sandbox read-denies were bypassable through `sandbox.excludedCommands`** — any entry lifts the OS sandbox for the **entire** command line, so `git push -h >/dev/null 2>&1; <read of a denied path>` exited 0 where the bare read got EPERM. `surfpool *` and `anchor test*` stay because Surfpool needs unsandboxed Mach access; the six git/gh entries stay because a sandboxed `git push` cannot reach the ssh-agent socket or the gh token. The secrets hook inspects each statement of the command line, so the read in `git push -h; <read>` is still blocked.
- **`anchor test` was broken on a default install** — `surfpool start` panics instantly under the Bash sandbox (macOS SystemConfiguration), which also took out `/test-rust`, `/test-ts`, `/profile-cu` and `/debug-user-tx` on Anchor 1.x's default path. `network.allowLocalBinding` does not cover it.
- **`cargo build` could not write its registry cache** — the toolchain roots (`~/.cargo/**`, `~/.rustup/**`, `~/.cache/solana/**`, `~/.local/share/solana/**`, `~/.avm/**`) are now carved out of the outside-write deny at every tier, with credentials and `config.toml` still denied.
- **`/update` and `/add-skill` failed at `mktemp -d` under the sandbox** — the platform temp root is now writable at every tier. The same failure truncated a tracked file when an unguarded variable expanded to empty.
- **Two-wildcard permission patterns never matched** — a mid-pattern `*` does not match an empty string, so `Bash(anchor * --final*)` did not stop `anchor --final`, and `Bash(git push * -f *)` did not stop `git push origin -f`. Every two-wildcard rule now ships its zero-gap twin.
- **`permissions.ask` rules never fired** — verified twice in-session: `git clean -n` matched an ask rule and ran silently while a deny rule blocked `sudo -n true`, with the sandbox on. Every prompt is now a hook returning `permissionDecision: "ask"`; no tier distinction rests on `permissions.ask`.
- **`Bash(git clean -fd *)` and `Bash(git push --force *)` sat in both `deny` and `ask`** — deny wins, so both ask rules were dead. The lists are de-duplicated and a test forbids any pattern appearing in both.
- **The secrets hook matched command prose instead of argument positions** — it blocked a diagnostic `ls -l` on a wallet path, a `gh issue create` whose body mentioned `--final`, and heredocs that merely named a credential directory.
